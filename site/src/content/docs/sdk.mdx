---
title: Go SDK
description: The Go packages the CLI is built on, for use in other programs.
---

The CLI is built on a Go SDK in `pkg/`. Other programs import it as `github.com/Cloverhound/webex-cli/pkg/...`; Webex Admin Studio is built on it. The packages hold no process-wide state, and every call takes a context.

| Package | What it is |
|---|---|
| `webexapi` | HTTP transport: 401 refresh, 429 retry, structured errors, lists that fail instead of ending short, hosts for every data region and Contact Center data center, org ID conversion, Contact Center pacing. |
| `webexops` | Every API operation as data, generated from Cisco's Postman collections: route, parameters, body fields, paging. `Call` sends one. |
| `resource` | Object types as data: fields, JSON paths, write mode, and the operations each type uses. |
| `catalog` | The object types, and which can be written. |
| `webex` | Reads and writes objects by type. |
| `guard` | The write protocol: a conflict check before a write, a read-back after it, and a stop after a failure. |
| `changeset` | The change set file format that Webex Admin Studio imports and exports. |
| `aiagent` | AI Agent Studio's private routes: agent token lookup and credential redaction. |
| `fakeapi` | A fake Webex for tests, with fault injection. |

## Calling an operation

Each operation is an exported variable named after its CLI command, such as `webexops.CCTeamGet` for `webex cc team get`. A program that uses one fails to build when a Postman refresh drops or renames it.

```go
hosts, err := webexapi.NewHosts("us1", "us") // Contact Center data center, data region
api := &webexapi.Client{
	Token:      func(ctx context.Context) (string, error) { return token, nil },
	MaxRetries: 3,
}
resp, err := webexops.Call(ctx, api, hosts, webexops.CCTeamGet, webexops.Args{
	Path: map[string]string{"orgid": orgUUID, "id": teamID},
})
```

`Args` names parameters as the API does. A path parameter without a value, or a parameter the operation does not have, is an error, so a misspelled name is never silently dropped. Bodies and responses are JSON: Postman's example bodies do not match what Webex returns, so generated types would be wrong.

## Objects by type

```go
c := &webex.Client{API: api, Hosts: hosts, OrgUUID: orgUUID}
queue, _ := catalog.ByName("cc_queue")

queues, err := c.List(ctx, queue)            // every queue, fields by name
q, err := c.Read(ctx, queue, queues[0].Key)

planned := resource.Values{}
for k, v := range q.Values {
	planned[k] = v
}
planned["max_time_in_queue"] = int64(900)

g := &guard.Guard{API: c, Writable: true}
values, err := g.Update(ctx, queue, q.Key, q.Values, planned)
```

`guard.Update` re-reads the object and refuses if it changed since `q` was read, sends the change the way the route needs (the whole object for a Contact Center `PUT`), and reads the result back. A `*guard.Failure` says whether Webex refused the write, whether its outcome is unknown, or whether the object ended up different from the plan.

## Regions

`webexapi.NewHosts` takes the org's Contact Center data center (`us1`, `eu1`, `eu2`, `anz1`, `ca1`, `jp1`, `sg1`) and data region (`us`, `ca`, `eu`, `eun`, `in`, `au`). Each Contact Center data center has its own AI Agent Studio host. Contact Center refuses bursts of more than about 25 requests a second; give the client a `webexapi.Pacer` on the Contact Center host as `BeforeSend` to stay below that.
