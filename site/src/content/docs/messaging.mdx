The `webex messaging` (alias: `webex msg`) subcommand provides access to the Webex Messaging APIs for managing rooms, messages, teams, and webhooks.

## Resource Groups

| Resource | Description |
|----------|-------------|
| `attachment-actions` | Attachment action management |
| `ecm-folder-linking` | ECM folder linking |
| `events` | Event management |
| `hds` | Hybrid Data Security management |
| `memberships` | Room membership management |
| `messages` | Message management |
| `people` | People in messaging context |
| `room-tabs` | Room tab management |
| `rooms` | Room (space) management |
| `team-memberships` | Team membership management |
| `teams` | Team management |
| `webhooks` | Webhook management |

## Common Patterns

```bash
# List resources
webex messaging <resource> list

# Get by ID
webex messaging <resource> get --id "..."

# Create
webex messaging <resource> create --body-file config.json

# Update
webex messaging <resource> update --id "..." --body-file updated.json

# Delete
webex messaging <resource> delete --id "..."
```

## Examples

```bash
# List rooms
webex messaging rooms list --paginate

# List messages in a room
webex messaging messages list --room-id "ROOM_ID"

# List teams
webex messaging teams list

# List team memberships
webex messaging team-memberships list --team-id "TEAM_ID"

# List webhooks
webex messaging webhooks list

# List room memberships
webex messaging memberships list --room-id "ROOM_ID"
```

## File Attachments

The existing `files` array accepts one HTTP(S) URL or one local file path, in either `--body` or `--body-file` JSON. A URL uses the normal JSON request; a local path automatically uploads the file as `multipart/form-data`.

```bash
# Upload a local file to a direct message
webex messaging messages create --body '{"toPersonEmail":"user@example.com","text":"Guide attached","files":["./guide.md"]}'

# Preview a JSON body saved on disk (no message is sent)
webex messaging messages create --body-file message.json --dry-run

# Existing URL attachments still work
webex messaging messages create --body '{"roomId":"ROOM_ID","files":["https://example.com/guide.pdf"]}'
```

Relative local paths are resolved from the CLI's **current working directory**, not the JSON body's directory. Absolute paths also work; JSON values do not expand `~` or environment variables. Use filesystem paths rather than `file://` URLs. For MCP, paths refer to files on the server's machine, not a remote chat client's machine.

Local uploads require a regular file of at most **100 MiB**. Files are buffered in memory to support token-refresh and rate-limit retries. One attachment is supported per message; multiple files and mixed local/remote entries are rejected. Other fields in a local-upload body must be strings, so structured values such as Adaptive Card `attachments` are not supported alongside a local file. Remote URL requests retain their JSON fields unchanged.

Dry-run validates the file and shows its path and size without uploading it. Debug and dry-run output do not print attachment contents; read-only mode blocks uploads. Only attach local files you intend to share.

## Hybrid Data Security

Use `webex messaging hds` (`hybrid-data-security` is a group alias) to inspect organizations, clusters, nodes, network-test results, alarms, and resource usage. The overlapping upstream groups are consolidated.

```bash
webex messaging hds list-clusters-org --organization-id <id>
webex messaging hds list-nodes-cluster --cluster-id <id>
webex messaging hds get-alarms-node --node-id <id>
webex messaging hds get-usage-node --node-id <id>
```

Distinct older routes remain separate: `get-database-org` versus `get-database-config-org`, and `get-multi-tenant-org` versus `list-tenants-org`. Existing numeric spellings remain aliases for the latter two operations.
